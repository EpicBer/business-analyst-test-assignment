# Тестовое задание для бизнес-аналитика: BPMN и SQL

Репозиторий содержит две независимые части тестового задания:

1. Моделирование процесса оформления пропусков в BPMN 2.0.
2. Проверка качества данных PostgreSQL с помощью SQL.

## Структура репозитория

```text
.
├── README.md
├── bpmn/
│   ├── task.md
│   └── result/
│       └── README.md
└── sql/
    ├── task.md
    ├── solution.sql
    └── database/
        ├── schema.sql
        └── data.sql
```

## Порядок выполнения

1. Прочитайте [задание BPMN](bpmn/task.md).
2. Разместите результат BPMN в каталоге `bpmn/result/`.
3. Прочитайте [задание SQL](sql/task.md).
4. Разверните тестовую базу по инструкции.
5. Заполните файл `sql/solution.sql`.
6. Дополните этот README кратким описанием выполненной работы и командами запуска.
7. Разместите результат в собственном репозитории GitHub и отправьте ссылку.

## Ограничения

- Не изменяйте `sql/database/schema.sql` и `sql/database/data.sql`.
- Не добавляйте в репозиторий пароли, токены и другие секреты.
- Все файлы решения должны открываться без специализированного коммерческого ПО.

## Что отправить

- ссылку на GitHub-репозиторий;
- путь к BPMN-схеме для быстрого просмотра;
- команду запуска SQL-решения.

## Немного о выполненной работе
Найденные проблемы в задании с бд:
1. Документ AA1002 принадлежит двум людям.
2. У заявки 105 окончание периода раньше начала.
3. У заявок 103, 104 и 115 отсутствуют обязательные положительные согласования.
4. Пропуска 3005, 3006 и 3017 ошибочно разрешают автомобильный доступ.
5. В четырёх пропусках записаны несогласованные зоны.
6. У пропусков 3011, 3014, 3015 и 3018 нарушены требования к датам активного пропуска.
7. Для заявки 110 существуют два активных пропуска.
8. Пропуск 3012 выдан и событие 5015 зарегистрировано раньше создания заявки 112.
9.  Дата согласования заявки 121 раньше даты её создания.

В задании на создание была разработана модель процесса оформления пропуска на территорию промышленного предприятия.
Из-за большого количества связей между задачами, модель была разделена на 4 диаграммы для сохранения читаемости. Краткая информация по составляющим описана в файле notes.md.
