# Задание SQL: проверка данных системы пропусков

## Цель

Представьте, что вы проверяете данные системы оформления пропусков.

В PostgreSQL-базе намеренно допущены ошибки. Напишите SQL-запросы, которые находят эти ошибки, не изменяя данные.

## 1. Подготовка базы

Из корня репозитория выполните:

```bash
createdb pass_sql_test
psql -v ON_ERROR_STOP=1 -d pass_sql_test -f sql/database/schema.sql
psql -v ON_ERROR_STOP=1 -d pass_sql_test -f sql/database/data.sql
```

Проверьте загрузку:

```bash
psql -d pass_sql_test -c "SELECT COUNT(*) FROM pass_test.pass_requests;"
psql -d pass_sql_test -c "SELECT COUNT(*) FROM pass_test.passes;"
```

Ожидается 21 заявка и 19 пропусков.

Заполняйте файл `sql/solution.sql`. В его начале уже установлена схема `pass_test`.

## 2. Основные таблицы

| Таблица          | Содержание                 |
| ---------------- | -------------------------- |
| `persons`        | Получатели пропусков       |
| `pass_requests`  | Заявки                     |
| `approvals`      | Результаты согласований    |
| `zones`          | Справочник зон             |
| `request_zones`  | Согласование зон заявки    |
| `passes`         | Выпущенные пропуска        |
| `pass_zones`     | Зоны, записанные в пропуск |
| `request_events` | История обработки заявок   |

Подробный состав полей находится в `sql/database/schema.sql`.

## 3. Задания

Каждый запрос должен возвращать только ошибочные записи. Не указывайте в запросах заранее известные идентификаторы.

### 1. Повторяющиеся документы

Найдите номера документов, принадлежащие нескольким людям.

Выведите номер документа и количество людей. Используйте `GROUP BY` и `HAVING`.

### 2. Некорректные периоды действия

Найдите заявки, у которых дата окончания раньше даты начала.

Выведите идентификатор заявки, даты начала и окончания, статус.

### 3. Отсутствующие обязательные согласования

У заявки со статусом `APPROVED` должны быть два положительных решения:

- `SECURITY`;
- `MANAGER`.

Найдите заявки, у которых отсутствует хотя бы одно такое решение.

Выведите идентификатор заявки, решение службы безопасности и решение руководителя. Каждая заявка должна присутствовать один раз.

### 4. Ошибочно разрешённый автомобильный доступ

Автомобильный доступ разрешается, только если автомобиль запрошен и транспортная служба приняла решение `APPROVED`.

Найдите пропуска с `vehicle_access_allowed = TRUE`, для которых одно из условий не выполнено.

Выведите идентификаторы пропуска и заявки, признак запроса автомобиля и решение транспортной службы.

### 5. Несогласованные зоны

В пропуск могут быть записаны только зоны со статусом `APPROVED` в заявке.

Найдите зоны, которые отсутствуют в заявке либо имеют решение `REJECTED` или `PENDING`.

Выведите номер пропуска, идентификатор заявки, название зоны и решение.

### 6. Ошибки активных пропусков

У активного пропуска должны быть даты выдачи и активации, не должно быть даты отзыва, а активация не может быть раньше выдачи.

Найдите нарушения и выведите идентификатор, номер и даты пропуска.

### 7. Несколько активных пропусков

Найдите заявки, для которых существует более одного пропуска со статусом `ACTIVE`.

Выведите идентификатор заявки и количество активных пропусков.

### 8. Статистика заявок

Для каждой пары «тип пропуска — статус» выведите количество заявок.

Отсортируйте результат по типу и статусу.

## 4. Дополнительное задание

Дополнительное задание выполнять необязательно.

Найдите пропуска, заявки или события, даты которых нарушают последовательность процесса: выдача, согласование или событие произошли раньше создания заявки.

## 5. Ограничения

Запрещается:

- изменять исходные данные;
- использовать `INSERT`, `UPDATE`, `DELETE`, `TRUNCATE`, `DROP` или `ALTER`;
- изменять `schema.sql` и `data.sql`;
- использовать заранее известные идентификаторы ошибочных записей;
- использовать `SELECT *` в итоговых запросах.

Разрешаются `JOIN`, `LEFT JOIN`, `GROUP BY`, `HAVING`, подзапросы, `EXISTS`, `NOT EXISTS`, CTE, `CASE` и агрегатные функции.

## 6. Проверка решения

Файл должен выполняться без ошибок:

```bash
psql -v ON_ERROR_STOP=1 -d pass_sql_test -f sql/solution.sql
```

Добавьте в корневой `README.md` краткий перечень найденных проблем.
